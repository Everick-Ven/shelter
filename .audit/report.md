## 2. Что НЕ проверено (и ручной чек-лист владельца)

- **Реальный CEF 154 / GPU / Windows / macOS** — рендер шёл в headless
  Chromium 129 (sparticuz, CDP): честно, что это не CEF 154. Ручная проверка:
  1) стартовый экран во всех 6 темах (свечение карточки против эталона);
  2) стоимость `backdrop-filter` при скролке списков на слабом GPU;
  3) скроллбары и размеры кнопок окна на macOS (шрифты локальные — ок);
  4) поведение `:focus-visible` в CEF 154 (в 129 рамки у #heroInput нет ни
  при одном пути фокуса — см. §3.3а).
- **Навыки `impeccable`/`taste-skill`/`emil-design-eng`** в среде отсутствуют
  (`~/.claude/skills/` нет): аудит делался «по коду» с их правилами из ТЗ;
  `impeccable detect/polish` не запускались — не рапортую.
- **Замедление анимаций 10–25%** (DevTools Animations) недоступно в headless:
  ревью движения — чтением кода + замером длительностей.
- **Прерываемость toasts/tips** (keyframes→transition): быстрые повторы не
  воспроизводились как проблема — оставлено как есть (§3, «отложено»).

### 3.3а Баг «белая рамка» #heroInput (ТЗ §2.9)

**На текущем коде не воспроизводится** (подтверждено замером): в состояниях
`:focus`+`:focus-visible` у поля `outline:none / box-shadow:none / border:0`
при трёх путях фокуса — программном, клике и Tab (`.audit/before/shots/
hero-focus-computed.json`, одинаково и в «после»). Пиксельный дифф
фокус/не-фокус по краю карточки идентичен. Яркое гало вокруг карточки,
видное на скриншотах, — **штатное свечение карточки** (canvas `#heroFx` +
`.omni-ring`-кайма): присутствует и без фокуса, переживает выключение
`.omni-ring`, теней и декора (кадр-увеличение:
`report-shots/edge-crop-glow-vs-frame.png`). Скриншот владельца, вероятно,
снят со сборки с иным набором быстрых ссылок («эталон») — как и предполагал
ТЗ. Правка сделана защитной (§2.9): поле не нарисует рамку ни при какой
комбинации правил. Эталонное «карточка со свечением как сейчас» — сохранено.

## 4. Критика по taste-skill (3 главные оставшиеся проблемы)

1. **Светлые темы компенсируют контраст потемнением серых** — ivory/porcelain/
   bordeaux теперь читаются, но их вторичный текст стал заметно «тяжелее»
   (text-2 4.4→6.5). Если владелец захочет лёгкости — см. вариант Б в §5.1.
2. **Микротипографика наград/чекаута выросла до 12px** — плотные карточки
   наград стали воздушнее; при желании вернуть 11px для бейджей —
   критерий 6 потребует пометить их как метки (вариант в §5.2).
3. **Гало стартового экрана читается как «рамка»** — при увеличенном
   контрасте это не изменилось; вопрос силы свечения — за владельцем (§5.4).

## 5. Решения для владельца (вкус, не баг)

1. **Сила вторичного текста в светлых темах.** Вариант А (сделано):
   `--text-2`→6.5:1, `--text-3`→4.65:1 — максимум читаемости. Вариант Б:
   `--text-2` 5.2:1 / `--text-3` 4.5:1 — легче, но шаг иерархии сожмётся
   до 1.1. Рекомендация: А (критерий 1 выполнен с запасом).
2. **Микрокопии наград/чекаута.** А (сделано): всё читаемое — 12px.
   Б: бейджи/теги (`.ach-status-tag`, `.premium-plan-badge`, `.ach-filter`) —
   11px как «метки». Рекомендация: А до жалоб на плотность.
3. **Градиентный текст** (`.hero-title em`, `.dt-welcome h1`): оставить /
   заменить на `--text` с той же типографикой / приглушить градиент до 70%.
   Не тронуто. Рекомендация: оставить — это идентичность Luxe.
4. **Сила свечения карточки омнибокса** (`#heroFx` + `.omni-ring`): рамкой
   воспринимается частью пользователей. Варианты: оставить / снизить
   `--halo`/`--tint` на 20–30% только у `.omni-ring` / выключить свечение
   в `perf`-режиме по умолчанию (сейчас только `#heroFx` гасится).
   Рекомендация: оставить до прогона на реальном CEF (§2, п.1).
5. **Тема по умолчанию и `prefers-color-scheme`**: сейчас `graphite`,
   системная настройка не используется. Варианты: оставить / добавить
   маппинг системной темы (light→ivory, dark→graphite) с ручным выбором
   поверх. Не тронуто (запрет менять тему по умолчанию без спроса).
6. **Файлы-двойники** (ТЗ §2.6): `index-2.html` удалён ранее (коммит
   `fa34c26`, «нереференсированная копия со старым unsafe-inline CSP»),
   `new port.html` удалён в `e2f7825` по прошлому ТЗ (P2-7: grep подтвердил
   неиспользование, −1.3МБ из сборки). Оба ещё есть в `main`.
   Рекомендация: согласиться с удалением при слиянии.
7. **Пульсирующие индикаторы** (`.rec i`, `dlRunBlink`, `shimmer`, `dlSweep`):
   привязаны к живому состоянию (см. §6) — оставлены. Если «пульс» тяжёл на
   слабом GPU — можно гасить в `perf`.
